# Spec Delta

## MODIFIED Requirements

### Requirement: 测试延迟
系统 SHALL 支持测试节点延迟。

#### Scenario: 测试单个节点延迟
- **WHEN** 用户点击节点的延迟区域
- **THEN** 调用 API 测试该节点延迟
- **AND** 更新显示的延迟值

#### Scenario: 测试组内所有节点延迟
- **WHEN** 用户点击"测全部延迟"按钮
- **THEN** 对组内各节点分别执行延迟测试
- **AND** 显示加载状态
- **AND** 完成后更新所有延迟值

#### Scenario: 加载状态限于目标代理组
- **WHEN** 用户对某个代理组触发测延迟
- **THEN** 进行中状态仅作用于该代理组
- **AND** 其余代理组保持可交互，不进入加载状态
- **AND** 页面不因该操作整体塌陷为加载态

#### Scenario: 每个节点具有独立的进行中状态
- **WHEN** 组内多个节点正在被测试
- **THEN** 每个节点各自显示其进行中状态
- **AND** 一个节点的测试完成不影响其他节点仍在进行中

#### Scenario: 延迟结果陆续到达
- **WHEN** 组内各节点的延迟测试陆续完成
- **THEN** 每个节点在自身结果到达时立即更新其延迟值
- **AND** 不等待全部节点完成才统一刷新
- **AND** 先完成的节点不因其他节点仍在测试而被阻塞

#### Scenario: 测延迟期间防止重复触发
- **WHEN** 某代理组正在测延迟
- **THEN** 该组的测延迟操作不可被重复触发
- **AND** 其他代理组的测延迟操作不受影响

#### Scenario: 测延迟失败可见
- **WHEN** 测延迟请求失败
- **THEN** 以错误语义提示失败原因
- **AND** 该组恢复为可操作状态

#### Scenario: 测延迟中断后的状态收敛
- **WHEN** 测延迟过程中结果通道中断且未收到完成信号
- **THEN** 该组所有节点退出进行中状态
- **AND** 未获得结果的节点以超时语义呈现

### Requirement: 选中代理不刷新
系统 SHALL 在选中代理后不重新拉取数据。

#### Scenario: 选中代理
- **WHEN** 用户点击选择一个代理
- **THEN** 调用 API 切换代理
- **AND** 仅更新本地状态中的 `now` 值
- **AND** 页面不重新渲染或闪烁

#### Scenario: 选中后立即可见
- **WHEN** 用户点击选择一个代理
- **THEN** 界面立即反映该节点处于选中状态
- **AND** 不等待服务端响应后才改变显示

#### Scenario: 选中失败回滚
- **WHEN** 切换代理的请求被服务端拒绝
- **THEN** 界面恢复为切换前的选中节点
- **AND** 以错误语义提示切换失败
